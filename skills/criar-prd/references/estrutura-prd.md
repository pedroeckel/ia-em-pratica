# Uma definição simples do projeto

Adapte o tamanho e os títulos. Não inclua seções vazias só para completar o modelo.

1. **O que queremos resolver:** situação atual e problema observado.
2. **Para quem:** quem usará ou será beneficiado pela entrega.
3. **Resultado desejado:** o que deverá melhorar; diga como será percebido.
4. **O que vamos entregar:** itens necessários, com prioridades se houver escolha.
5. **O que não faz parte agora:** limites para evitar expectativas diferentes.
6. **Como conferir se está pronto:** resultado esperado para cada item importante.
7. **O que falta decidir ou obter:** informações, pessoas, materiais e restrições.

Se útil, organize os itens em duas colunas: “O que precisamos” e “Como conferir”.
Inclua prazo, orçamento e responsáveis apenas se conhecidos ou como propostas
identificadas. Um projeto complexo pode precisar de mais detalhes; isso não torna
os detalhes obrigatórios para projetos pequenos.

## Exemplo fora de tecnologia

Pedido: “Quero melhorar a recepção de novos funcionários da loja.”

Definição inicial possível: criar um guia de boas-vindas e um roteiro para o
primeiro dia. O guia deve explicar horários, contatos e regras fornecidas pela
loja; o roteiro deve indicar as atividades de apresentação. A entrega estará
pronta quando os itens combinados estiverem presentes e os dados forem conferidos
com as fontes. Reduzir o tempo de adaptação é um resultado a medir depois.

Quantidade de funcionários, regras, contatos, prazo e responsáveis não foram
informados. Não preencha esses campos com dados inventados. Ainda é possível
preparar a estrutura e perguntar pelos dados necessários.
